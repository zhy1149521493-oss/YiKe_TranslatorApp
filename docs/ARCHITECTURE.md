# Runtime architecture and request lifecycle

## Stable view and drawer motion

The three layouts retain the drawer and main shell across task/Settings changes. `useViewMotion` keys only an opacity transition to view identity, with interruption, keyboard/reduced-motion cancellation and unmount cleanup. Native workspace geometry keeps the same 240ms timing as CSS for both directions, including a simultaneous menu removal. Standalone navigation uses 160ms. See [motion lifecycle and validation](MOTION.md).

## Main-window menu and audio reading

The [context menu](CONTEXT_MENU.md) is owned by ConnectedMain and scoped to the production main window. Its optional popup rectangle is serialized with native navigation-region updates and unioned on the UI thread, preserving desktop hit testing while folded. Pinning reads and writes actual Tauri window state without persisting business configuration. Poetry alone groups AudioRecognized/AudioTranslations by source in one reading column; controllers, queues, native ASR and landscape layouts are unchanged.

## Isolated design preview

The production main window sizes itself after saved design preferences hydrate. `useStyleWindowSize.ts` supplies Tauri monitor/window/storage operations to the serialized `StyleWindowSizing` controller. Style-specific normal sizes are device-local, use logical pixels and ignore our own resize events; maximized/minimized geometry never becomes a saved normal size. A main-only capability adds minimum-size control. Native drawer clipping still determines the visible/hit surface independently of expanded geometry. See [sizes, golden-ratio reading measure and compatibility](POETRY_LAYOUT.md).

The connected [Poetry reading page](POETRY_LAYOUT.md) keeps a natural vertical document. Its original editor observes container width, viewport resize and offline font readiness to remeasure actual text height without the old oversized minimum. The observers are detached on unmount. Screenshot/subtitle presentation uses compact status/controls instead of a duplicate capture placeholder; native recognition commands and business state remain owned by MainWindow.

`demo.html` and `src/demo/main.tsx` form a separate entry. `model.ts` owns typed fixture state and shared appearance preferences; `usePreview.ts` is an in-memory task/clipboard adapter. Layout, translation, recognition, settings and floating-panel components consume this single controller. They import no production controller or Tauri APIs. `vite.demo.config.ts` builds `dist-demo/`, separately from the main app. See [design demo boundaries and validation](DESIGN_DEMO.md). The user has authorized integration; `src/interface/` is the separate production presentation layer described below. The Demo continues to use fixtures.

`workspace.ts` controls only task/settings visibility; closing a workspace never calls the task adapter's stop action. `Disclosure.tsx` provides nonmodal page disclosures with native buttons, `aria-expanded`/`aria-controls`, inert folded content, focus recovery, pointer-leave delay and touch activation. It keeps the current content mounted when folded. Navigation selection derives from workspace visibility plus its task/settings view, rather than the retained mode alone; a folded workspace has no selected task or Settings entry. These are application page regions, not modal dialogs or menus, and add no UI runtime dependency. CSS uses transform/opacity/clip-path transitions and progressive mount entry, with instant keyboard/reduced-motion behavior. The isolated `navigation` preference defaults to `persistent` and accepts `hover`. All three layouts share the behavior while retaining their navigation silhouettes. Disclosure expansion is the union of persistent mode, open workspace, pointer reveal and keyboard-visible navigation focus; workspace visibility takes priority over hover departure. Workbench and Classic keep their original layout tracks even in hover mode, avoiding content occlusion and animated reflow. Focus does not cancel a pending pointer-leave timer. Pointer presses clear a previous keyboard pin, and mouse/touch focus on task buttons cannot pin disclosure; this prevents needing an extra blank-area click after folding. Escape on an open workspace reaches the page visibility controller before navigation can fold. `BrandMark.tsx` owns the themed outline; `demo.html` references the cleaned app SVG only for this entry, leaving production icons untouched. The three main navigation silhouettes remain; the retired desktop Capsule launcher is unrelated to these disclosures.

`ReadingWorkbench.tsx` keeps the studio rail/top model bar, shared text-language controls and bottom action. Its editor and paired-reading view share task state. `fixturePairs` accepts only complete, explicitly known sample fixtures; it does not infer alignment from paragraph counts. `Features.tsx` puts Workbench recognized source cards below left capture/listening controls, separate from right translations.

`model.ts` stores computer/microphone tasks and source/target languages under `audioChannels`. The legacy-shaped `tasks.audio` field is a derived summary for status and aggregate copy, never the channel display store. `usePreview.ts` owns independent channel timers; stop clears both, and active-source changes preserve channel data while cancelling inactive pending work. `AudioTranscript.tsx` renders labelled per-channel source/result cards and independent language/copy controls across main styles and the audio preview. Fixtures are deterministic, not streaming ASR or production queue integration.

`Floating.tsx` renders the Classic translation/subtitle header/body or a separate audio panel on a simulated desktop. Floating-style preferences normalize to Classic, including older Capsule values. The Capsule launcher/edge geometry module has been removed from the current candidate. Title dragging, bounded resize and audio collapse/stop semantics remain. All windows use shared appearance tokens. Monitor work areas, always-on-top/transparency, native window synchronization and full-page visual acceptance remain unverified.

## Components

The main-window [native drawer surface](NATIVE_DRAWER.md) is synchronized by `src/interface/useNativeSurface.ts` and `nativeSurface.ts`. Its main-only `set_main_surface` IPC applies a Windows region in `src-tauri/src/main_surface.rs`; hidden areas neither paint nor intercept desktop input. The WebView keeps its expanded canvas size, so window clipping does not trigger narrow-layout breakpoints or remount business state.

`src/App.tsx` routes to main, translation floating, audio floating or screenshot overlay components using the native window label. The main window owns configuration and provider selection, and orchestrates translation. React and CSS are embedded into the portable executable by the Tauri CLI release build.

`src/interface/` implements the connected Poetry/Workbench/Classic presentation. `controller.ts` defines live view data and explicit commands; MainWindow retains configuration, inference routing, queues and native handlers. `ConnectedMain` owns workspace visibility only. Original settings forms and classic text controls remain slots; native floating components remain in App.tsx. CSS is scoped to `.connected-ui` so auxiliary windows retain their original layout. `src/assets/fonts/` supplies shared offline fonts to production and Demo. `settings.design` stores the new style/navigation separately from the legacy `settings.uiLayout` fallback. See [configuration and functional mapping](INTERFACE_INTEGRATION.md). `scripts/ui-preview.mjs` supplies development-only fixture IPC and is not included in the production frontend.

`src/text-tools.ts` provides bounded language heuristics and conservative normalized subtitle deduplication. Uncertain source detection returns `auto`; prompts then ask the model to detect the original language. These heuristics do not replace a full language-identification model.

`src/request.ts` bounds the complete translation operation to 60 seconds. Its AbortSignal is passed to local Ollama fetch calls, including body reads. For native API IPC calls, the UI task settles on cancellation and the channel ignores late callbacks; the HTTP operation itself currently runs until its existing native timeout/completion.

`src/latest-task.ts` serializes main text, video, screenshot and clipboard work per queue, keeping the newest pending request. Input/settings changes, stop/close and effect cleanup invalidate prior results. Video OCR returns directly to its requesting polling effect, so old frame results cannot become events in a new session. Screenshot OCR keeps source and request context together.

`src/audio-tasks.ts` has independent queues for system audio and microphone. Jobs include a native session ID and utterance ID, source, text and final state. Pending partials coalesce; finals are preserved rather than overwritten by the next partial. Pending work is bounded to three jobs per queue. Display history retains three entries per source, preventing computer audio from evicting microphone entries. Recognition events own history finalization; results update matching source/IDs/text. A partial result cannot overwrite a finalized line. Stopping or changing translation settings invalidates the queue.

`src-tauri/src/lib.rs` implements commands, portable resource paths, provider HTTP requests, OCR/capture and window orchestration. `streaming.rs` decodes byte-buffered SSE; `capture_bounds.rs` translates validated physical desktop rectangles into monitor-local crops. A crop must fit one monitor; cross-monitor or stale/out-of-bounds regions return an error instead of panicking.

`src-tauri/src/audio.rs` owns WASAPI capture and sherpa-onnx recognition. The engine-map mutex protects short state operations; a separate lifecycle mutex serializes start/stop/restart. Engine snapshots do not carry the map lock into loops, and capture threads are joined after releasing it. Start/stop commands use the blocking worker pool. Each recognizer start assigns a monotonic session ID, and each endpoint advances an utterance ID. `audio_samples.rs` decodes supported formats and handles silent packets without reading the packet pointer.

Audio floating windows have an event-only capability for status listening and close notifications. Recognition is forwarded directly by native eval to `__audioPartial` / `__audioFinal`; translated output is forwarded to `__audioShow`. Shared reducers attach text/results by identity in both the main and floating windows.

## Changed internal IPC contracts

These interfaces are internal. Ship matching frontend and backend binaries; consumers of the old events/return values must migrate as follows.

| Command/event | Current shape and behavior | Previous behavior |
| --- | --- | --- |
| `capture_fullscreen` | Returns `{ b64, x, y }`; `x/y` are the primary monitor's physical desktop origin. Overlay image crops remain image-local, while emitted regions add the desktop origin. | Returned only the base64 string and selected the first enumerated monitor. |
| `screenshot_ocr` | Returns its own OCR text or rejects with an error, using a blocking worker. | Returned `processing`, later emitted a shared `ocr-done` event. |
| `subtitle_frame` | Returns OCR text, including `ERROR:` messages, directly to the requesting poll. | Returned `processing`, later emitted `subtitle-ocr`. |
| `audio-status` | `{ source, session, status }`; obsolete sessions and explicitly stopped sources are ignored. | Had no session field. |
| `audio-partial` / `audio-final` | `{ source, session, id, text }`; `id` is `session:utterance`. Native partial/final window injection uses the same object. | Had only source/text; window partial injection took a string. |
| `audio_forward_to_floating` | Requires `id` and `session` in addition to source/text/language/result/role. Results update existing history by identity. | Updated whichever line occupied the current/previous position when translation finished. |
| `audio_subtitle_start` / `audio_subtitle_stop` | Asynchronous commands using blocking workers; success resolves without a payload, failure rejects. | Synchronous start/stop could block IPC while joining/reloading capture. |

Configuration remains version 3, with the existing paths and keys. Restored subtitle coordinates are interpreted as physical desktop coordinates. Regions saved by older builds assumed a zero-origin primary monitor; reselect the region if the display arrangement changed. Default subtitle capture uses the monitor containing the main window; the screenshot-selection overlay currently covers the primary monitor.
