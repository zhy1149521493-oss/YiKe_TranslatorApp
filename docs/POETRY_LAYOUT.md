# Responsive Poetry reading layout

The Poetry workspace remains one continuous vertical reading page. Original text, its editing actions and the translation follow one another in document order. The toolbar, paper texture, serif typography and native drawer behavior remain in place. The centered text/OCR reading column uses 61.8% of the page width, capped at 1040 CSS pixels and bounded by available space and a 320-pixel readable minimum. At window widths of 600 CSS pixels or less it uses the available inner width instead. Screenshot/subtitle controls share that column so the page has one consistent alignment. Reading text uses a minimum 20-pixel serif size (18 at narrow widths), or the larger saved reading size.

## Default window orientation

The connected main window defaults to 640×860 logical pixels for Poetry and 960×640 for Workbench/Classic. These are preferences, not locked orientations. Each style remembers manual normal-window resizing independently on this device. Switching styles in Settings restores that style's size. A maximized or minimized window is left in that state; on restoration the selected style's normal size is applied. Startup sizing waits for configuration hydration, so a saved Poetry selection does not first receive the Workbench size.

Poetry's normal minimum is 560×480; the other styles retain 720×480. Sizes are clamped to the current monitor's usable work area with a 32-logical-pixel allowance, and positions are corrected if enlargement would put the window outside that monitor. On very small displays, available work area takes precedence over the minimum. Logical sizes follow Windows DPI scaling. Additional monitor/DPI combinations remain to be verified.

Only window geometry uses device-local WebView storage (`yike.main-window.sizes.v1`), independently of the portable business configuration. Moving the app to another device starts with defaults. Invalid stored dimensions are ignored. Storage failure falls back to session-only memory. Folding still uses the native clipping region and does not overwrite remembered expanded sizes. Classic auxiliary floating windows are unaffected.

Empty and short passages fill the available reading page vertically: the source uses a height-sensitive minimum and the translation takes remaining space, keeping the result actions near the foot of the page instead of leaving an empty lower half. This is a minimum page height, not a fixed content height or equal-height split. The editor grows with actual text and remeasures after window/container width changes or offline font loading. Clearing text shrinks it again. Long passages continue down the page and may require page scrolling. Short windows reduce minimums and separators. Settings retain their existing page scrolling.

Screenshot and subtitle pages in all three main styles no longer render the large dashed capture placeholder or repeat recognized text in it. Their compact control area retains screen selection, screenshot translation, subtitle start/stop, FPS, region readiness, status and the system OCR test. Poetry uses a single control stack with wrapping buttons and aligned source/result sections. Audio keeps independent computer/microphone data, labels, languages and real meters; at <=800 CSS pixels its controls and source/result sections stack vertically, while wider windows retain separate columns. Explicit wide-screen grid positions are reset in the narrow layout to prevent implicit columns. Auxiliary Classic floating windows are unchanged.

## Implementation and verification

`src/interface/poetry.css` owns the reading measure, responsive spacing and thin theme-aware page scrollbar. `Translation.tsx` remeasures the flowing editor with a width observer, resize listener and font readiness callback; cleanup detaches them. `Features.tsx` provides the compact capture summary. `windowSizing.ts` validates stored geometry, plans sizes and serializes style transitions; `useStyleWindowSize.ts` adapts it to Tauri window events and device-local storage. The main-only `main-sizing` capability permits changing the minimum size. The desktop controller, task queues, OCR/ASR commands and saved configuration schema are unchanged.

Run `npm test` and `npm run build` from the repository root. Regression tests render long original/result content without truncation, exercise editor remeasurement/cleanup, and check that capture, language, FPS and OCR-test controls remain present after removing the placeholder. Sizing tests cover defaults, work-area bounds, corrupt storage, independent custom dimensions, maximization/restoration, rapid switching, disposal, native-error recovery and delayed configuration hydration. These tests do not prove visual sizing. Desktop acceptance must check the 640×860 Poetry default, 560×480 minimum, 960×640 landscape alternatives, maximized view, long passages, light/dark colors, capture/subtitle controls and folding/reopening. Device OCR/ASR accuracy is outside this layout change.

The current revision passes 72 frontend checks, ten Rust tests and the TypeScript/Vite/Tauri embedded release build. Native visual checks covered all four Poetry pages in the normal portrait window, aligned screenshot/subtitle controls and visible page-foot actions, single-source audio without implicit columns, light/dark paper views, maximum-size text/OCR layouts, restoration, settings-only landscape Workbench/Classic switching and returning to the independently remembered portrait size. Fold-to-logo and reopening were checked after restoration. The app was left on Poetry text with the original dark theme and hover preference. Native automation needed a system-menu restore after a maximized UI Automation click landed on a navigation button; this was not treated as proof that the custom restore button failed.

Minimum-width geometry, additional DPI/monitor combinations, long live model output and simultaneous live audio still require broader native acceptance. Existing content-growth/source-identity regression tests cover those data paths, not device accuracy or every visual size. The rejected earlier equal-height/wide-column and intermediate unbalanced-orientation builds are not this revision.
